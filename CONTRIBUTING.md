# Contributing to crisplogs

Thanks for taking the time to contribute. This document covers the local development workflow.

## Prerequisites

- Node.js 18 or newer (the package targets `>=18.0.0` at runtime; 20 LTS is recommended for development).
- npm 9+ (ships with recent Node releases).

## Local setup

```bash
git clone https://github.com/Dev22603/crisplogs-js.git
cd crisplogs-js
npm ci
```

`npm ci` installs from `package-lock.json` for a reproducible dependency tree. Use `npm install` only when intentionally updating a dependency.

## Day-to-day commands

| Command | What it does |
|---------|--------------|
| `npm test` | Run the vitest suite once (CI mode) |
| `npm run test:watch` | Watch-mode vitest for iterative work |
| `npm run lint` | Lint `src/` and `tests/` with Biome |
| `npm run lint:fix` | Apply Biome's auto-fixes |
| `npm run build` | Build dual ESM + CJS bundles into `dist/` via tsup |

`prepublishOnly` runs `lint` and `build` automatically, so you cannot publish broken code.

## Project layout

```
src/        TypeScript source — what gets bundled
tests/      Vitest tests, one file per source module + a shared helper
examples/   Runnable scripts demonstrating each feature
dist/       Build output (gitignored, regenerated by `npm run build`)
```

The public API lives entirely in `src/index.ts`. Anything that should be importable from `"crisplogs"` must be re-exported there.

## Testing

- One test file per source module (`src/foo.ts` → `tests/foo.test.ts`).
- Use `tests/helpers.ts::makeRecord()` to construct fixture `LogRecord` objects.
- Tests that call `setupLogging` should clean up to avoid handler accumulation. The existing tests use unique `name` values per test or `resetLogging()`.
- Always cover error paths when adding validation; the typed errors (`InvalidLevelError`, etc.) make `expect(...).toThrow(InvalidLevelError)` straightforward.

## Style

- Biome enforces formatting and lint rules; run `npm run lint:fix` before committing.
- Public symbols need JSDoc with `@param`, `@returns`, `@throws` (where applicable), and at least one `@example`.
- Keep `dist/` out of commits; it's a build output.

## Releasing

Releases are tag-driven:

1. Bump the version in `package.json` (semver; 0.x allows breaking changes between minors).
2. Update `CHANGELOG.md` — move the `[Unreleased]` block under a new dated heading.
3. Commit with a message like `chore: release v0.3.0`.
4. Tag (`git tag v0.3.0`) and push (`git push --follow-tags`).
5. Create a GitHub Release for the tag. The publish workflow (when configured) will run `npm publish` with provenance.

If you need to publish manually: `npm publish` from a clean checkout. `prepublishOnly` will run lint + build first.

## Reporting issues

Open an issue at <https://github.com/Dev22603/crisplogs-js/issues>. A minimal reproduction (the exact `setupLogging` options and a snippet that triggers the problem) is the fastest path to a fix.
